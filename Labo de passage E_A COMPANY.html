0

Faire l’inventaire du diagramme

Avant d’appliquer une règle, classez chaque élément. L’algorithme traite d’abord les entités, pour que chaque clé primaire existe avant qu’une clé étrangère en ait besoin.

  • Entités fortes : EMPLOYEE, DEPARTMENT, PROJECT.
  • Entité faible : DEPENDENT (double rectangle), identifiée par DEPENDENTS_OF (double losange).
  • Associations binaires : MANAGES 1:1 · WORKS_FOR 1:N · CONTROLS 1:N · SUPERVISION 1:N réflexive · WORKS_ON M:N.
  • Attributs particuliers : Name est composé, Locations est multivalué, Number_of_employees est dérivé.
DEPARTMENT et PROJECT ont chacune deux attributs soulignés (Name et Number) : les deux sont des clés. Nous en choisirons une comme clé primaire et garderons l’autre UNIQUE.
1

Traduire les entités fortes

Règle · Étape 1Pour chaque entité forte E, créez une relation R avec tous les attributs simples de E. Pour un attribut composé, ne gardez que ses composants simples. Choisissez une clé de E comme clé primaire de R.
  • EMPLOYEE : l’attribut composé Name est décomposé en Fname, Minit, Lname ; Ssn est la clé, il devient la clé primaire.
  • DEPARTMENT : Name et Number sont toutes deux des clés. Nous choisissons Number comme clé primaire (courte, stable) et déclarons Name UNIQUE. Les attributs sont renommés Dname, Dnumber pour rester clairs une fois les relations jointes.
  • PROJECT : même raisonnement : Pnumber est la clé primaire, Pname est UNIQUE, Location devient Plocation.
  • Reporté : l’attribut multivalué Locations attend l’étape 6 ; l’attribut dérivé Number_of_employees n’est pas stocké (voir la fin du parcours).
EMPLOYEE(Fname, Minit, Lname, Ssn, Bdate, Address, Gender, Salary) DEPARTMENT(Dname, Dnumber) Dname UNIQUE PROJECT(Pname, Pnumber, Plocation) Pname UNIQUE
entité → relationcomposé → composantsclé → PKautre clé → UNIQUE
2

Traduire l’entité faible

Règle · Étape 2Pour chaque entité faible W de propriétaire E, créez une relation R avec les attributs simples de W, plus la clé primaire de E comme clé étrangère. La clé primaire de R combine la clé du propriétaire et la clé partielle de W.
  • Le propriétaire de DEPENDENT est EMPLOYEE (via l’association identifiante DEPENDENTS_OF) : DEPENDENT reçoit donc Essn → EMPLOYEE.Ssn.
  • La clé partielle Name (soulignée en pointillé) devient Dependent_name.
  • PK = (Essn, Dependent_name) : deux employés peuvent chacun avoir un ayant droit nommé Alice.
  • L’association identifiante DEPENDENTS_OF n’a pas besoin de relation propre : la clé étrangère Essn la représente déjà.
DEPENDENT(Essn, Dependent_name, Gender, Birth_date, Relationship) FK Essn → EMPLOYEE(Ssn) ON DELETE CASCADE
Utilisez ON DELETE CASCADE : un ayant droit ne peut pas exister sans son employé (dépendance d’existence).
3

Traduire l’association binaire 1:1

Règle · Étape 3 (approche par clé étrangère)Pour une association 1:1 entre S et T, placez la clé primaire de T comme clé étrangère dans S, en choisissant pour S l’entité à participation totale. Les attributs de l’association vont aussi dans S.
  • MANAGES relie EMPLOYEE (1) et DEPARTMENT (1). Le trait double est du côté DEPARTMENT : chaque département a un directeur, mais la plupart des employés ne dirigent rien.
  • DEPARTMENT joue donc le rôle de S : il reçoit Mgr_ssn → EMPLOYEE.Ssn, déclaré NOT NULL (participation totale).
  • L’attribut d’association Start_date devient Mgr_start_date dans DEPARTMENT.
  • Mgr_ssn est aussi déclaré UNIQUE, car un employé dirige au plus un département. Sans UNIQUE, l’association devient silencieusement 1:N.
DEPARTMENT(Dname, Dnumber, Mgr_ssn, Mgr_start_date) FK Mgr_ssn → EMPLOYEE(Ssn) NOT NULL, UNIQUE
Pourquoi ne pas mettre la clé étrangère dans EMPLOYEE ?

Cela fonctionnerait, mais la plupart des employés ne sont pas directeurs : la colonne serait NULL dans presque toutes les lignes. Choisir le côté à participation totale évite ces NULL.

Les deux autres options de l’étape 3 sont une relation fusionnée (seulement si les deux côtés sont totaux) et une relation de liaison ; aucune ne convient ici.

4

Traduire les associations binaires 1:N

Règle · Étape 4Pour une association 1:N, repérez la relation S du côté N. Placez la clé primaire de la relation T du côté 1 dans S comme clé étrangère, avec les éventuels attributs de l’association.
  • WORKS_FOR (DEPARTMENT 1 : N EMPLOYEE) : EMPLOYEE reçoit Dno → DEPARTMENT.Dnumber. La participation totale d’EMPLOYEE la rend NOT NULL.
  • CONTROLS (DEPARTMENT 1 : N PROJECT) : PROJECT reçoit Dnum → DEPARTMENT.Dnumber, NOT NULL (tout projet est contrôlé).
  • SUPERVISION est réflexive : le côté supervisé (N) est EMPLOYEE et le côté superviseur (1) aussi. EMPLOYEE reçoit Super_ssn → EMPLOYEE.Ssn, nommée d’après le rôle. Elle peut être NULL : le dirigeant suprême n’a pas de superviseur.
EMPLOYEE(Fname, Minit, Lname, Ssn, Bdate, Address, Gender, Salary, Super_ssn, Dno) PROJECT(Pname, Pnumber, Plocation, Dnum)
Ne mettez jamais la clé étrangère du côté 1 : DEPARTMENT aurait besoin d’une liste de numéros d’employés, ce qui n’est pas une valeur atomique.
5

Traduire l’association binaire M:N

Règle · Étape 5Pour une association M:N, créez une nouvelle relation contenant les clés primaires des deux participants comme clés étrangères. Leur combinaison est la clé primaire. Les attributs de l’association y sont ajoutés.
  • WORKS_ON relie EMPLOYEE (M) et PROJECT (N) : un employé travaille sur plusieurs projets et un projet a plusieurs employés.
  • Nouvelle relation WORKS_ON avec Essn → EMPLOYEE.Ssn et Pno → PROJECT.Pnumber ; PK = (Essn, Pno).
  • L’attribut d’association Hours appartient au couple (employé, projet) : il va donc dans WORKS_ON.
WORKS_ON(Essn, Pno, Hours)
Une association M:N donne toujours une relation séparée, même sans attribut.
6

Traduire l’attribut multivalué

Règle · Étape 6Pour chaque attribut multivalué A d’une entité E, créez une nouvelle relation avec A et la clé primaire de E comme clé étrangère. La clé primaire combine les deux.
  • Locations (double ovale) appartient à DEPARTMENT : un département peut être situé dans plusieurs villes.
  • Nouvelle relation DEPT_LOCATIONS avec Dnumber → DEPARTMENT.Dnumber et Dlocation ; PK = (Dnumber, Dlocation).
DEPT_LOCATIONS(Dnumber, Dlocation) ex. (5, Bellaire) (5, Sugarland) (5, Houston)
Garder Locations dans DEPARTMENT (« Bellaire, Sugarland, Houston ») violerait l’atomicité (1FN).
7

Traduire les associations n-aires

Règle · Étape 7Pour chaque association à plus de deux participants, créez une nouvelle relation avec les clés primaires de tous les participants comme clés étrangères (plus les attributs de l’association). Sa clé primaire est en général la combinaison de ces clés étrangères.
  • Toutes les associations du diagramme COMPANY sont binaires : l’étape 7 n’ajoute donc rien ici.
  • On la vérifie quand même : sauter une étape en connaissance de cause fait partie de l’application correcte de l’algorithme.
— aucune nouvelle relation —
✓

Traiter l’attribut dérivé

Règle · Attributs dérivésUn attribut dérivé n’est pas stocké : il est calculé à partir d’autres données quand on en a besoin, en général par une requête ou une vue.
  • Number_of_employees (ovale pointillé) se calcule en comptant les tuples EMPLOYEE de chaque département, grâce à la clé étrangère Dno.
  • Le stocker créerait une valeur fausse après chaque embauche ou départ, sauf mise à jour automatique.
CREATE VIEW DEPT_SIZE AS SELECT Dno AS Dnumber, COUNT(*) AS Number_of_employees FROM EMPLOYEE GROUP BY Dno;

Ce que les clés étrangères ne peuvent pas imposer

Certaines contraintes de participation du diagramme n’ont pas d’équivalent dans le schéma. Il faut les imposer par des triggers, des assertions ou l’application :

  • Chaque DEPARTMENT a au moins un employé (participation totale de DEPARTMENT dans WORKS_FOR).
  • Chaque EMPLOYEE travaille sur au moins un projet, et chaque PROJECT a au moins un employé (participation totale des deux côtés de WORKS_ON).

La participation totale du côté qui porte la clé étrangère (1:N ou 1:1) est traduite par NOT NULL (Dno, Dnum, Mgr_ssn) ; la participation totale du côté 1 ou dans une association M:N ne l’est pas.

Implémentation

Le schéma en SQL

EMPLOYEE référence DEPARTMENT (Dno) et DEPARTMENT référence EMPLOYEE (Mgr_ssn) : c’est un cycle. On crée d’abord les tables, puis on ajoute la clé étrangère restante avec ALTER TABLE.

CREATE TABLE EMPLOYEE (
  Fname      VARCHAR(15)  NOT NULL,
  Minit      CHAR(1),
  Lname      VARCHAR(15)  NOT NULL,
  Ssn        CHAR(9)      PRIMARY KEY,             -- étape 1
  Bdate      DATE,
  Address    VARCHAR(50),
  Gender     CHAR(1),
  Salary     DECIMAL(10,2) CHECK (Salary >= 0),
  Super_ssn  CHAR(9),                            -- étape 4, SUPERVISION (peut être NULL)
  Dno        INT          NOT NULL,                -- étape 4, WORKS_FOR (totale)
  FOREIGN KEY (Super_ssn) REFERENCES EMPLOYEE(Ssn)
);

CREATE TABLE DEPARTMENT (
  Dname          VARCHAR(25) NOT NULL UNIQUE,       -- clé alternative
  Dnumber        INT         PRIMARY KEY,
  Mgr_ssn        CHAR(9)     NOT NULL UNIQUE,       -- étape 3, MANAGES (1:1, totale)
  Mgr_start_date DATE,
  FOREIGN KEY (Mgr_ssn) REFERENCES EMPLOYEE(Ssn)
);

ALTER TABLE EMPLOYEE ADD FOREIGN KEY (Dno) REFERENCES DEPARTMENT(Dnumber);

CREATE TABLE DEPT_LOCATIONS (                      -- étape 6
  Dnumber   INT,
  Dlocation VARCHAR(15),
  PRIMARY KEY (Dnumber, Dlocation),
  FOREIGN KEY (Dnumber) REFERENCES DEPARTMENT(Dnumber) ON DELETE CASCADE
);

CREATE TABLE PROJECT (
  Pname     VARCHAR(25) NOT NULL UNIQUE,
  Pnumber   INT         PRIMARY KEY,
  Plocation VARCHAR(15),
  Dnum      INT         NOT NULL,                -- étape 4, CONTROLS (totale)
  FOREIGN KEY (Dnum) REFERENCES DEPARTMENT(Dnumber)
);

CREATE TABLE WORKS_ON (                            -- étape 5
  Essn  CHAR(9),
  Pno   INT,
  Hours DECIMAL(3,1),
  PRIMARY KEY (Essn, Pno),
  FOREIGN KEY (Essn) REFERENCES EMPLOYEE(Ssn),
  FOREIGN KEY (Pno)  REFERENCES PROJECT(Pnumber)
);

CREATE TABLE DEPENDENT (                           -- étape 2
  Essn           CHAR(9),
  Dependent_name VARCHAR(15),
  Gender         CHAR(1),
  Birth_date     DATE,
  Relationship   VARCHAR(8),
  PRIMARY KEY (Essn, Dependent_name),
  FOREIGN KEY (Essn) REFERENCES EMPLOYEE(Ssn) ON DELETE CASCADE
);
