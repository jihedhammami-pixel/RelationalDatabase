STEP 1

Check the requirements

Oracle's installer runs a set of prerequisite checks and stops if one fails. Check these points before you download almost 2 GB.

RequirementWhat Oracle's documentation states for XE 21c on Windows
Operating systemWindows 10 x64 (Pro, Pro for Workstations, Enterprise, Education) or Windows Server 2012 R2, 2016, 2019 x64. Windows Home editions are not supported.
Memory2 GB of RAM minimum.
Disk space8.5 GB minimum for the Oracle software, plus 2 GB or more of temporary storage.
AccountYou must be logged on as a direct member of the Administrators group. Indirect membership, or only running the installer "as administrator", is not sufficient.
EnvironmentORACLE_HOME and TNS_ADMIN must not be set at the system level (unsetting them in a command prompt is not enough).
Existing XEUninstall any existing Oracle Database XE, or any database with the SID XE. Only one XE installation is allowed per machine.
About Windows 11. The 21c XE requirements table lists Windows 10 and Windows Server only, so Windows 11 is not on Oracle's list. The installer's own check requires Windows version 10 or higher and refuses Home editions.

Check your Windows edition

Press Win + R, type winver and press Enter. The window shows your edition and version.

winver

Check for ORACLE_HOME

In PowerShell, these two commands should print nothing. If they print a value, remove the variable in System Properties → Environment Variables.

[Environment]::GetEnvironmentVariable("ORACLE_HOME","Machine") [Environment]::GetEnvironmentVariable("TNS_ADMIN","Machine")
STEP 2

Download the installer

Download the Windows version of Oracle Database 21c Express Edition from Oracle's official download page.

Windows x64OracleXE213_Win64.zip1,967,615,483 bytes (about 1.97 GB)
Open Oracle's XE download page ↗

Optional, verify the file. Oracle publishes this SHA-256 checksum on the download page:

939742c3305c466566a55f607638621b6aa7033a183175f6bcd6cffb48e6bc3f

In PowerShell, from your Downloads folder, compare it with:

Get-FileHash .\OracleXE213_Win64.zip -Algorithm SHA256
STEP 3

Extract the zip and run setup.exe

  1. Right-click OracleXE213_Win64.zip → Extract All… to a temporary folder, for example C:\xe_temp.
  2. Open the extracted folder and find setup.exe.
  3. Make sure you are logged on with an account that is a direct member of Administrators, then double-click setup.exe. Any missing prerequisites are installed first, then the InstallShield wizard opens.
Pick a destination path without spaces in the next step. Oracle's guide states this explicitly.

STEP 5

Check the services and connect

XE runs as Windows services. Check that they are running, then connect with SQL*Plus, which is installed with XE.

Windows services

Press Win + R, type services.msc, press Enter, and look for:

  • OracleServiceXE: the database.
  • OracleOraDB21HomenTNSListener: the listener. The number n depends on Oracle homes already on your PC.

Both should show Running. Right-click → Start if not. Under Properties you can set the startup type to Automatic or Manual.

Services and ports

  • Listener port 1521 (default; the first free port from 1521 is used).
  • Service XE = the root container CDB$ROOT.
  • Service XEPDB1 = the default pluggable database. This is where you work and where HR goes.
  • XEPDB1 opens automatically when the database starts.

Connect with SQL*Plus

Open a Command Prompt. Check that the listener knows both services:

lsnrctl status

Connect to the pluggable database as SYSTEM (you will be asked for the password chosen during installation):

sqlplus system@localhost:1521/XEPDB1

Or connect as SYS to the root container with your Windows account (works even if the listener is stopped), and list the PDBs:

sqlplus / as sysdba SHOW PDBS

If Windows says sqlplus is not recognized, run it from the Oracle home: C:\app\<username>\product\21.0.0\dbhomeXE\bin\sqlplus.exe (default location).

STEP 6

Install the HR sample schema

XE does not include HR. Oracle publishes the sample schemas on GitHub, and the current scripts support Oracle Database 19c and higher, so they work with 21c XE.

1 · Download the scripts

  1. Open the db-sample-schemas releases page ↗.
  2. Under the release marked Latest, download Source code (zip).
  3. Extract it, for example to C:\oracle-samples. The folder is named after the release (for v23.3: db-sample-schemas-23.3).

2 · Why XEPDB1 and not XE?

HR is an ordinary (local) user, so it must be created inside a pluggable database. In the root container CDB$ROOT the script fails with ORA-65096: invalid common user or role name. Always connect to XEPDB1.

Run the script as a privileged user that can create and drop users, such as SYSTEM.

3 · Run hr_install.sql from its folder

Start SQL*Plus from inside the human_resources folder: hr_install.sql calls hr_create.sql, hr_populate.sql and hr_code.sql from the same folder.

cd C:\oracle-samples\db-sample-schemas-23.3\human_resources sqlplus system@localhost:1521/XEPDB1

At the SQL> prompt:

@hr_install.sql

STEP 9
Troubleshooting
The errors students meet most often in this lab, and what to do.

      

        
ORA-65096 invalid common user or role name
You ran hr_install.sql while connected to the root container (service XE). Reconnect with sqlplus system@localhost:1521/XEPDB1 and run it again.

        
ORA-12541 no listener
The listener service is stopped. Start OracleOraDB21HomenTNSListener in services.msc, or check the port shown by lsnrctl status.

        
ORA-12514 listener does not currently know of service
Check the service name (XEPDB1) and that OracleServiceXE is running. lsnrctl status lists the services the listener knows; when the database is down, none appear.

        
ORA-01017 invalid username/password
For SYSTEM, use the password you chose in the installer (it is shared by SYS, SYSTEM and PDBADMIN). For HR, use the password entered in hr_install.sql.

        
SP2-0310 unable to open file
SQL*Plus cannot find a script. Start SQL*Plus from inside the human_resources folder (step 6.3), or give the full path after @.

        
A prerequisite check fails
Confirm you use a supported Windows edition (not Home), that your account is a direct member of Administrators, that ORACLE_HOME and TNS_ADMIN are not set system-wide, and that no XE is already installed. Installation logs are in %Program Files%\Oracle\Inventory\logs.
